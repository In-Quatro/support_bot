Полный рабочий проект Telegram-бота на Python (aiogram v3, асинхронная БД aiosqlite), упакованный для запуска через Docker и Docker Compose для деплоя на VPS.

### 🎯 НАЗНАЧЕНИЕ БОТА
Бот предназначен для приема заявок от пользователей в техническую поддержку и запроса картриджей, а также для работы специалистов с этими заявками. Везде в интерфейсе используется слово «Специалист» (не «Инженер»).

---

### 📋 ФУНКЦИОНАЛ И СЦЕНАРИИ

#### 0. Регистрация и доступ (обязательно для пользования ботом)
- При первом обращении бот просит заполнить 5 полей (пошагово, с валидацией):
  1. ФИО (минимум имя + фамилия)
  2. Телефон (кнопкой «Отправить номер» или вручную, проверка формата)
  3. Номер поликлиники сокращённо (например, «ГП №5»)
  4. Адрес поликлиники
  5. Должность
- После заполнения заявка на доступ отправляется в закрытый чат специалистов с кнопками:
  - ✅ **Одобрить** — доступ открывается, пользователь получает уведомление;
  - ❌ **Отклонить** — у специалиста запрашивается причина, пользователь получает её уведомлением.
- До одобрения все разделы бота закрыты: при попытке пользоваться бот сообщает, что заявка на рассмотрении (или причину отказа + кнопку повторного запроса).
- Отклонённый пользователь может отправить запрос повторно («📨 Запросить доступ повторно») после проверки данных в «👤 Мои данные».
- Пользователи, уже имеющие заявки в БД, считаются одобренными автоматически (миграция при старте).

#### 1. Для пользователей (ЛС с ботом)
- **Главное меню:**
  - 📝 Создать заявку в ТП
  - 🖨 Запросить картридж
  - 📁 Мои обращения
  - 👤 Мои данные (ФИО, телефон, поликлиника, адрес, должность, статус доступа + правка каждого поля)
- **Поликлиника и адрес подтягиваются из профиля:** при создании заявки/запроса бот показывает «Поликлиника: … / Адрес: … / Данные верны?» с кнопками «✅ Верно» / «✏️ Ввести свои» — вводить каждый раз не нужно.
- **Сценарий 1: Заявка в ТП (пошаговый опрос / FSM):**
  1. Подтверждение поликлиники/адреса (из профиля или свои)
  2. Номер технологической точки — строго формат `000-0000` (пример: `001-0001`), валидация regex `^\d{3}-\d{4}$`
  3. Номер кабинета
  4. IP-адрес АРМ (валидация через `ipaddress`, пример: `10.15.25.35`)
  5. Описание проблемы
  6. Фото (опционально, пропустить или до 3-х фото, настраивается `MAX_PHOTOS`)
  7. Проверка: предпросмотр + кнопки ✏️ правки **каждого** поля (повторный ввод → возврат к проверке)
  8. Подтверждение отправки.
  *После отправки заявка получает уникальный ID из БД (например, #1001) и уходит в рабочий чат специалистов.*
- **Сценарий 2: Запрос картриджей — сначала выбор направления поставки:**
  - 🖨 **На один принтер:** только номер технологической точки (проверка формата) + номер кабинета. Количество всегда 1 автоматически. Модель не спрашивается (точка идентифицирует принтер).
  - 🏥 **На всю поликлинику:** множественный выбор галочками из каталога (CF280 / CF226 / CF287 / CF259 / DL-5120 / TL-5120), затем комментарий. Количества НЕ спрашиваются.
  - Каталог: CF280 (HP M401/M425), CF226 (HP M426), CF287 (HP M501), CF259 (HP M404), DL-5120 (PANTUM), TL-5120 (PANTUM).
  - Далее: комментарий (можно пропустить) → проверка с ✏️ правками → отправка как заявка типа «Картриджи».
  - В чате специалистов модели выводятся каждая с новой строки.
- **Сценарий 3: «Мои обращения»:**
  - Список обращений (ID, дата в формате `ДД.ММ.ГГГГ ЧЧ:ММ`, тип, статус: «Новая», «В работе», «Выполнена», «Отклонена»).
  - Клик → подробная карточка (без строки «Ответственный» — она видна только в чате специалистов). Выполненную/отклонённую заявку можно «↩️ Вернуть в работу» с комментарием (статус → «В работе», карточка в чате обновляется, комментарий постится в ветку заявки).
- **Переписка по заявке:** сообщения специалистов приходят отдельными сообщениями с подсказкой «Чтобы ответить — ответьте на это сообщение (Reply)». Ответ пользователя (Reply) уходит в ветку заявки в чате специалистов с подписью «ФИО (Номер поликлиники)». Поддерживаются текст и фото в обе стороны.

---

#### 2. Для специалистов (работа в общем закрытом чате)
- Все новые заявки «сливаются» в единый закрытый Telegram-чат специалистов, заявки на доступ — туда же.
- Карточка заявки: структурированные данные, инициатор (ФИО + телефон), ответственный, фото отдельными сообщениями, инлайн-кнопки:
  - 🛠 **В работу** → статус «В работе», карточка правится, пользователю: *«Ваша заявка #ID взята в работу. Ожидайте выполнения.»* (без ника специалиста);
  - ✅ **Выполнено** → статус + уведомление (*«…Если проблема осталась — верните её в работу из «📁 Мои обращения»*»);
  - ❌ **Отклонить** → запрос причины у специалиста → статус + уведомление с причиной;
  - 🔄 **Взять на себя** (у заявок «В работе») — смена ответственного, карточка правится, пользователю ничего не отправляется;
  - ✉️ **Написать пользователю** (у заявок в любом статусе) — следующее сообщение специалиста уходит пользователю по этой заявке.
- Комментарий пользователю можно отправить ответом (Reply) на карточку заявки или командой `/comment <id> <текст>`.
- `/status <id>` — быстрый просмотр заявки в чате.
- Одобрение/отклонение запросов доступа — кнопками на карточке запроса (отклонение с причиной).
- Если пользователь заблокировал бота — в чат пишется предупреждение, бот не падает.

#### 3. Админ-панель (ЛС, доступ по Telegram ID из `ADMIN_IDS`)
- Команда `/admin`: весь список пользователей в формате «Номер поликлиники — ФИО» (по 20 на странице, пагинация), 🔍 поиск по ФИО/телефону/поликлинике/адресу/должности/username/ID.
- Карточка пользователя: все данные + статус доступа; правка ФИО/адреса/поликлиники; одобрение/отклонение ожидающих (с причиной), закрытие/открытие доступа (пользователь уведомляется).

### 🛠 ТЕХНИЧЕСКИЙ СТЭК И ТРЕБОВАНИЯ

1. **Язык и библиотеки:** Python 3.11+, `aiogram 3.x`, `aiosqlite`, `pydantic-settings`, `python-dotenv`.
2. **База данных (SQLite, WAL), с автоматической мягкой миграцией старых БД:**
   - `users(id, telegram_id UNIQUE, full_name, username, fio, phone, clinic_short, address, position, access['pending'|'approved'|'denied'], access_reason, access_by, access_msg_id)`.
   - `tickets(id, user_id, telegram_id, type['support'|'cartridge'], clinic_num, address, tech_point, cabinet, ip_address, printer_model, quantity, description, photos_json[file_id...], status['new'|'in_progress'|'done'|'rejected'], reject_reason, engineer_username, engineer_msg_id, author_name, author_phone, reopen_comment, scope['point'|'clinic'], created_at, updated_at)`.
   - `msg_links(ticket_id, engineer_msg_id, user_msg_id)` — связки веток переписки.
3. **Фото:** хранятся через `file_id` Telegram + best-effort локальная копия в `./data/photos/ticket_<id>/` (ошибки не роняют заявку).
4. **Конфигурация:** `BOT_TOKEN`, `GROUP_CHAT_ID`, `ADMIN_IDS` (ID через запятую) из `.env` через `pydantic-settings`; опционально `DB_PATH`, `PHOTOS_DIR`, `MAX_PHOTOS`.
5. **Контейнеризация:**
   - `Dockerfile` (python slim).
   - `docker-compose.yml` с volume `./data:/app/data` (БД и фото переживают перезапуски).
   - `.env.example`, `requirements.txt`, `.dockerignore`, `.gitignore` (секреты `.env`, `data/`, `.venv/` не коммитятся).

### 📂 СТРУКТУРА ПРОЕКТА
- `bot.py` (точка входа, инициализация, роутеры)
- `config.py` (чтение .env)
- `database/` (`__init__.py`, `db.py` — init/миграции, CRUD заявок, профилей, доступа, связок переписки)
- `handlers/` (`user_handlers.py` — ЛС: регистрация, опросы, обращения, возвраты, ветки переписки; `engineer_handlers.py` — чат специалистов; `admin_handlers.py` — /admin; `fsm_states.py` — SupportForm/CartridgeForm/ProfileForm/RejectForm/AccessForm/AdminForm/WriteForm; `common.py` — карточки, даты `ДД.ММ.ГГГГ ЧЧ:ММ`, уведомления, фото)
- `keyboards/` (`reply.py` — меню, отмена/пропуск/подтверждение/телефон; `inline.py` — управление заявкой, правки полей, каталог картриджей, доступ, админка)
- `Dockerfile` и `docker-compose.yml`
- `README.md`: как это работает, деплой на VPS за 3 шага, сборка Docker-образа вручную по шагам, выкладка на GitHub по шагам, админ-панель, схема БД.

Чистый рабочеспособный код с комментариями и обработкой ошибок (заблокировавший бота пользователь, недоступный чат, битые фото, невалидный ввод на каждом шаге).
